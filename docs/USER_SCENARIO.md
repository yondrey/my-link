# 마이링크 사용자 시나리오 (USER_SCENARIO)

본 문서는 링크트리 클론 서비스인 **"마이링크 (MyLink)"**에서 사용자(방문자 및 소유자)가 수행할 수 있는 다양한 행동 흐름과 예외 상황들을 다루는 사용자 시나리오 정의서입니다. 모든 시나리오는 기획 규정에 맞추어 `"사용자는 ~하기 위해 ~한다"` 형식으로 통일하여 서술합니다.

---

## 1. 방문자 (Visitor) 시나리오

### 1.1 마이링크 프로필 페이지 방문 및 탐색
* **프로필 정보 확인**:
  * 사용자는 **링크 목록을 제공하는 소유자가 누구인지 식별하고 그의 기본 약력을 이해하기 위해** 프로필 페이지 상단에 노출된 아바타 이미지, 실제 사용자 이름(`username`), 고유 닉네임(`@displayName`), 한 줄 소개(`bio`)를 탐색한다.
* **링크 카드 목록 탐색**:
  * 사용자는 **소유자가 작성한 활동 목록을 확인하고 원하는 정보가 있는 경로로 접근하기 위해** 공개 프로필 뷰 페이지에 수직으로 나열되어 있는 링크 리스트를 스크롤하여 탐색한다.
* **소셜 미디어 전용 아이콘 탐색**:
  * 사용자는 **소유자의 깃허브, 트위터, 인스타그램 등 주요 소셜 네트워크 계정을 방문하기 위해** 프로필 하단 또는 상단에 컴팩트하게 정렬된 소셜 아이콘 링크를 클릭한다.

### 1.2 링크 클릭 및 시스템 연동
* **링크 리다이렉션 및 클릭 수 카운트**:
  * 사용자는 **특정 링크 카드가 안내하는 목적지 웹사이트로 이동하고 소유자의 해당 링크 조회수를 누적해 주기 위해** 해당 링크 카드를 클릭하여 새 창으로 리다이렉트되는 동시에, 시스템이 해당 링크 도큐먼트의 클릭수(`clickCount`) 값을 1만큼 증가시키도록 트리거한다.

### 1.3 예외 상황 대응
* **존재하지 않는 프로필 경로 접근**:
  * 사용자는 **존재하지 않는 닉네임 주소로 잘못 접근했을 때 안내를 받고 메인 서비스 페이지로 이탈하거나 복귀하기 위해** `mylink.com/{invalid_displayName}` 주소로 접근하여 나타나는 404 에러 화면의 [홈으로 가기] 버튼을 클릭한다.

## 2. 소유자 (Owner) 시나리오

### 2.1 회원가입 및 로그인
* **구글 간편 회원가입 및 로그인**:
  * 사용자는 **별도의 이메일 가입 과정 없이 소셜 연동을 통해 내 멀티링크 페이지를 빠르게 개설하기 위해** 로그인 페이지의 [Google 계정으로 로그인] 버튼을 클릭하여 소셜 로그인 팝업 절차를 완료한다.
* **최초 가입 시 기본 정보 자동 연동**:
  * 사용자는 **첫 가입 시 복잡한 프로필 정보 입력 과정을 생략하기 위해** 구글 소셜 인증 완료 후 구글 지메일 아이디의 `@` 앞부분을 고유 `displayName`(URL 경로)으로 자동 부여받고, 구글 아바타 사진을 프로필 이미지(`photoURL`)로 연동하여 관리자 대시보드에 즉시 진입한다.
* **대시보드 리다이렉션**:
  * 사용자는 **기존에 가입한 계정 정보를 그대로 유지하여 링크 관리 화면에 진입하기 위해** 로그인을 시도하고 시스템이 Firestore의 사용자 UID 매핑 상태를 검증한 후 본인의 관리 대시보드 페이지로 정상 리다이렉트하게 한다.

### 2.2 프로필 정보 인라인 수정
* **displayName (닉네임 / URL 슬러그) 인라인 수정**:
  * 사용자는 **내 프로필 고유 웹 주소(슬러그)를 변경하기 위해** 대시보드의 `displayName` 영역을 클릭해 인라인 입력창을 띄우고 새로운 값을 입력한 뒤 포커스를 해제(Blur)하거나 엔터키를 입력하여 수정을 완료한다.
* **displayName 중복 설정 예외 처리**:
  * 사용자는 **이미 타인이 사용 중인 닉네임(슬러그)을 잘못 입력했을 때 수정을 복구하거나 다른 닉네임을 재입력하기 위해** 중복된 닉네임을 기입하고 수정을 완료하려 할 때 화면에 나타나는 "이미 사용 중인 닉네임입니다" 경고 메시지를 확인하고 입력을 취소(ESC 또는 공백 복구)한다.
* **username (실제 사용자 이름) 인라인 수정**:
  * 사용자는 **랜딩 페이지 프로필 타이틀로 보일 실제 성명이나 필명을 커스텀하기 위해** 대시보드 상의 `username` 영역을 마우스로 클릭하고 텍스트를 수정한 후 입력창 바깥을 클릭(Blur)하여 즉시 저장한다.
* **bio (한 줄 소개) 인라인 수정**:
  * 사용자는 **랜딩 페이지 하단에 제공할 나에 대한 소개 요약글을 변경하기 위해** 대시보드 내 `bio` 영역을 마우스로 선택하여 수정을 수행한 후 엔터키를 입력한다.

### 2.3 링크 관리 (인라인 CRUD)
* **새 링크 추가**:
  * 사용자는 **내 프로필 랜딩 페이지에 새로운 포트폴리오나 소셜 링크를 추가하기 위해** 대시보드 상단에 배치된 [새 링크 추가] 버튼을 클릭하여 링크 목록 최상단에 빈 임시 링크 카드를 생성한다.
* **링크 제목 및 URL 인라인 수정**:
  * 사용자는 **링크 버튼에 크게 표시될 설명 문구를 설정하기 위해** 생성된 링크 카드의 제목 텍스트 영역을 직접 클릭해 인라인 상태로 변경한 후 원하는 내용을 기입하고 포커스를 해제한다.
  * 사용자는 **방문자가 해당 링크 버튼을 눌렀을 때 이동할 타겟 목적지 주소를 입력하기 위해** 링크 카드의 URL 주소 입력 영역을 클릭하고 주소를 입력한 뒤 수정을 완료한다.
* **구글 API 기반 파비콘 아이콘 자동 연동**:
  * 사용자는 **링크의 아이콘을 수동으로 제작 또는 업로드하지 않고 도메인에 알맞은 파비콘이 자동 표시되게 하기 위해** URL 영역의 편집을 마쳐서 시스템이 입력된 도메인 주소를 토대로 구글 파비콘 API 주소(`https://www.google.com/s2/favicons?domain={domain}&sz=64`)를 매핑하여 Firestore에 함께 기록하도록 만든다.
* **비정상 URL 입력 예외 처리**:
  * 사용자는 **URL 형식을 완전히 갖추지 않은 주소(예: `http://` 또는 `https://` 프로토콜 유실)를 기입하여 렌더링 에러가 발생하는 것을 방지하기 위해** 잘못된 주소를 타이핑하고 입력을 완료하려 할 때 나타나는 경고 박스와 유효성 검사 실패 피드백을 확인하고 올바른 주소 형식으로 재입력한다.
* **링크 삭제**:
  * 사용자는 **더 이상 유효하지 않거나 공개하고 싶지 않은 링크를 내 마이링크 목록에서 제거하기 위해** 해당 링크 카드의 우측에 있는 [삭제] 버튼(휴지통 아이콘)을 클릭하고 팝업창에서 삭제를 최종 승인하여 Firestore 서브 컬렉션 데이터 및 화면에서 영구적으로 삭제한다.

### 2.4 본인 공개 프로필 뷰 페이지 내 바로가기 기능
* **대시보드 바로가기 연동**:
  * 사용자는 **내 공개 프로필 페이지의 렌더링 상태를 확인한 뒤 다시 링크 관리 대시보드로 신속히 복귀하기 위해** 구글 세션이 유지된 상태로 본인의 공개 경로(`mylink.com/{displayName}`)를 방문하여 나타나는 헤더 우측의 [대시보드로 가기] 바로가기 버튼을 클릭한다.
