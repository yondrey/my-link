# [PRD] 마이링크 (MyLink) - 개발자 및 크리에이터를 위한 심플 멀티링크 서비스

본 문서는 링크트리(Linktree) 클론 서비스인 **"마이링크 (MyLink)"**의 제품 요구사항 정의서(PRD)입니다. 본 서비스는 개발자와 크리에이터가 복잡한 기능 없이 직관적이고 심플하게 자신들의 포트폴리오, 소셜 미디어 활동, 작업물 링크를 하나로 묶어 제공할 수 있는 개인 맞춤형 랜딩 페이지를 제공합니다.

---

## 1. 프로젝트 개요

### 1.1 프로젝트명
* **마이링크 (MyLink)**

### 1.2 목적 및 배경
* **파편화된 링크 통합**: 개발자와 크리에이터가 운영하는 다양한 채널(GitHub, 블로그, YouTube, SNS 등)의 링크들을 하나의 고유한 URL(`mylink.com/{username}`)로 심플하게 통합합니다.
* **미니멀 UX 제공**: 불필요한 레이아웃과 복잡한 편집 기능(미리보기, 정렬 조작 등)을 배제하고, 핵심적인 링크 CRUD 및 파비콘 노출을 통해 빠르고 가볍게 동작하는 서비스 제공에 집중합니다.

### 1.3 대상 사용자 (Target Audience)
* **IT 개발자 및 엔지니어**: GitHub, 기술 블로그, 포트폴리오를 빠르게 공유하고자 하는 사용자.
* **크리에이터 및 프리랜서**: 자신들의 대표 채널 링크와 콘텐츠 링크를 직관적으로 나열하고자 하는 창작자.

## 2. 시스템 아키텍처 및 기술 스택

* **Frontend Framework**: Next.js (App Router, TypeScript)
* **Styling & UI**: Tailwind CSS, shadcn/ui (Radix UI 기반 UI 컴포넌트 라이브러리)
* **Authentication**: Firebase Authentication (구글 소셜 로그인 전용)
* **Database**: Firebase Firestore (서브 컬렉션 구조 활용)
* **Hosting**: Vercel

## 4. 기능 상세 설명

### F-01: Firebase 구글 로그인 & 회원가입 (필수)
* **설명**: 사용자는 Firebase Authentication을 사용해 구글 계정으로만 가입 및 로그인을 수행합니다.
* **동작 흐름**:
  1. 로그인 화면에서 구글 로그인 버튼 클릭.
  2. Firebase Auth 팝업창 활성화 후 로그인 수행.
  3. 최초 로그인인 경우 고유 아이디(`username`) 설정 페이지로 이동하여 가입 절차를 마무리하고, 기존 회원이면 대시보드로 이동.

### F-02: 고유 프로필 URL 생성 (필수)
* **설명**: 회원가입 완료 시 중복되지 않는 고유 영문/숫자 아이디(`username`)를 입력받아 프로필 경로로 사용합니다.
* **주소 구조**: `https://mylink.com/{username}`

### F-03: 프로필 기본 정보 설정 (필수)
* **설명**: 마이링크 랜딩 페이지 상단에 노출될 프로필 상세 정보를 설정합니다.
* **데이터 모델링 연동**:
  * **`displayName`**: 프로필 페이지 메인 닉네임으로 노출되는 필드 (데이터베이스 저장 시 `displayName` 키 명명 필수).
  * **아바타 이미지**: 사용자 프로필 사진 (Firebase Storage 업로드 후 URL 저장).
  * **한 줄 소개(Bio)**: 프로필 요약 설명글.

### F-04: 링크 관리 - CRUD (필수)
* **설명**: 프로필 페이지에 표시할 링크를 생성, 수정, 삭제합니다.
* **규칙 및 제한**:
  * 드래그 앤 드롭 정렬 기능 없음 (생성일시 `createdAt` 등 시스템 기준에 맞춰 순서 고정).
  * 활성/비활성 스위치 기능 없음 (삭제하거나 정보 수정만 지원).

### F-05: 링크 파비콘(Favicon) 자동 설정 (필수)
* **설명**: 사용자가 링크 아이템의 URL을 입력하면, 해당 사이트의 파비콘 이미지를 자동으로 가져와 링크 카드 아이콘으로 활용합니다.
* **구현 방식**:
  * 입력된 URL의 도메인(예: `https://github.com`)을 파싱하여 파비콘 제공 API(예: Google favicon API `https://www.google.com/s2/favicons?domain=...` 등)를 통해 파비콘 URL을 동적으로 추출하여 데이터베이스에 함께 저장합니다.

### F-06: 공개 프로필 뷰 페이지 (필수)
* **설명**: 외부 방문자가 접속하는 실제 페이지로, 설정된 프로필 이미지, `displayName`, 한 줄 소개, 그리고 파비콘 아이콘이 포함된 링크 리스트가 깔끔하게 렌더링됩니다.
* **미리보기 제한**: 관리 대시보드 내에 별도의 모바일 디바이스 프레임 미리보기(Live Preview) 기능은 구현하지 않으며, 공개 프로필 뷰 페이지를 직접 열어 확인합니다.

## 5. 데이터베이스 모델링 및 스키마 구조

Firebase Firestore를 기반으로 설계하며, 사용자와 링크의 관계를 효율적으로 관리하기 위해 **서브 컬렉션(Subcollection)** 구조를 적용합니다.

### 5.1 `users` 컬렉션
* 문서 경로: `/users/{userId}` (여기서 `userId`는 Firebase Auth UID)
```json
{
  "username": "yondrey",
  "displayName": "욘드리 개발자",
  "photoURL": "https://firebasestorage.googleapis.com/.../profile.jpg",
  "bio": "재미있는 것들을 만드는 웹 개발자입니다.",
  "createdAt": "2026-05-26T13:00:00.000Z"
}
```

### 5.2 `links` 서브 컬렉션
* 문서 경로: `/users/{userId}/links/{linkId}`
```json
{
  "title": "내 GitHub 저장소",
  "url": "https://github.com/yondrey",
  "faviconUrl": "https://www.google.com/s2/favicons?domain=github.com&sz=64",
  "createdAt": "2026-05-26T13:05:00.000Z"
}
```

## 6. 제외 기능 및 추후 추가 기능

### 6.1 제외된 기능 목록
본 단계에서는 미니멀한 MVP 제품 구성을 위해 아래 기능들을 기획 및 개발 대상에서 명확히 제외합니다.
* **드래그 앤 드롭 및 노출 순서 수동 제어**: 링크 정렬 조작 기능은 생략합니다.
* **링크 활성/비활성 스위치**: 노출 여부 토글을 지원하지 않으며, 노출을 원하지 않으면 삭제해야 합니다.
* **모바일 기기 뷰 실시간 미리보기**: 대시보드 화면에서의 실시간 장치 모킹 뷰를 제외합니다.
* **개발자 및 크리에이터 특화 컴포넌트**: GitHub 잔디, YouTube 동영상 바로 재생 등 서드파티 위젯 임베드 기능을 생략합니다.
* **선택적 추가 기능**: 예약 게시 설정, SEO 메타 커스텀 등 기존 기획의 모든 선택 기능을 제외합니다.

### 6.2 추후 추가 예정 기능
* **링크 클릭 조회수**: 방문자 분석 통계 대시보드 대신, 등록된 각 링크가 몇 번 클릭되었는지를 기록하고 단순 클릭 수를 프로필 관리자에게 보여주는 클릭 조회수 트래킹 기능을 추후 업데이트 버전에서 구현할 예정입니다.
